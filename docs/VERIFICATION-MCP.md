## Draft guard regression / draft保護の回帰修正

The added clean-save browser test failed against the original implementation: renaming Customer successfully left a global draft flag set, so an MCP update to Project never appeared. The correction tracks each form separately and clears its guard only after an acknowledged save, without clearing other forms. The companion test keeps both a field-label draft and a sample-value draft while saving the entity name, then verifies both survive an MCP update. Existing conflict, real disconnect/restart, and lost-response tests still pass. / 修正前に保存後の自動同期停止を再現し、フォーム単位の解除で修正。別フォームの実draftと既存の障害時保護を回帰確認。

## Reproduce / 再現

```sh
npm ci
npm run typecheck
npm test
npx playwright install chromium  # if not installed / 未導入時
npm run test:e2e                 # also builds / ビルドを含む
```

Shared mode and stdio host configuration examples are synchronized in [English](../README.md) and [日本語](../README.ja.md). Build first, start one server per document, open its loopback URL, and stop via its host or Ctrl+C. / 起動・停止・接続例は英日READMEを参照。

## Limits / 制約

- Codex/Claude host setup and a live LLM agent session were **not** run; no user settings, paid API, deployment or merge were performed. / 実エージェント接続は未確認。
- Local trusted processes, one authoritative store, synchronous file replacement and small models only. No automatic merge, offline queue or multiuser authentication. Draft guards are scoped to forms; acknowledged saves clear only their own scope. Remote edits require explicit reload only while unsent drafts remain, or after a conflict/disconnection. / 保存したフォームだけ保護を解除し、未送信draft・競合・切断時は明示再読込。
- No guarantee for network filesystems, hard-link aliases, power failure, all operating systems, all browsers or large-scale use. The file lock may need manual recovery after SIGKILL; never remove a live owner's lock. / 強制終了後のロック復旧等はREADMEを参照。
- UI screenshots, traces, temporary documents, dependencies and build outputs are ignored by Git. / 個人データ・認証情報・生成一時データは収録しない。
